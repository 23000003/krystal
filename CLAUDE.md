## What this is

"Krystal" — a voice-based mock-interview app. This project is the **SPA only**: no route handlers, no server logic, no secrets. Everything server-side lives in `../krystal-api` (NestJS, port 3001), which this app reaches over HTTP and a WebSocket.

Flow: `/` (upload a resume) → `/interview-session?id=X` (the live interview) → `/interview-session?id=X&result=true` (results).

## Architecture

Routes are thin; everything real lives outside `app/`.

- `app/` — App Router entries only. Each page composes from `features/` and does nothing else. `app/interview-session/page.tsx` serves **both** the interview and results screens, branching on the `result` search param.
- `features/<feature>/components|hooks/` — feature-scoped UI (`landing-page`, `interview-session`). `features/shared/` holds anything used by more than one.
- `config/constants.ts` — client constants plus `API_URL` / `WS_URL`, both derived from `NEXT_PUBLIC_API_URL` (defaults to `http://localhost:3001`).

Import via the `@/*` alias (project root).

Two hooks carry essentially all the behaviour:

- `features/landing-page/hooks/useUploadResume.ts` — TanStack Query mutation, axios to `POST {API_URL}/session`, toasts via sonner. Errors are typed `AxiosError<ApiResponse>`; `toMessage()` flattens `message: string | string[]`.
- `features/interview-session/hooks/useInterviewSession.ts` — the whole interview: WebSocket, phase machine, audio playback, MediaRecorder, and "Ready" keyword detection. `phaseRef` mirrors `phase` because the long-lived socket closure would otherwise read a stale value.

`features/shared/lib/wav.ts` converts MediaRecorder's webm/opus into the 16 kHz mono WAV the transcriber expects, and turns base64 WAV from the server into a playable object URL.

`features/shared/components/app-providers.tsx` mounts `QueryClientProvider` (client created in `useState`) and sonner's `<Toaster />`. It's in `features/`, not `app/`, per the rule that `app/` holds only router entries.

## Things that will bite

- **Browser-only paths are unverified.** Microphone capture, MediaRecorder, the WAV re-encode, playback, and keyword detection have never been exercised in a real browser — only typechecked and built. Backlog B-4.
- **"Ready" detection is Chrome/Edge only** (Web Speech API). The always-visible "I'm Ready" button is the fallback and the escape hatch when it mishears.
- **Autoplay may block `introduction.wav`** if the browser sees no user gesture on the new page. A "Tap to enable audio" button appears only when playback is refused.
- **Contract types are duplicated** with the API in `features/shared/types/`. The API owns the Zod schemas; these are plain types. Change one, change the other.
- `stt-code-reference.ts` and `tts-code-reference.ts` are vendor snippets, not built — excluded in both `tsconfig.json` and `eslint.config.mjs` because they contain placeholder syntax that doesn't parse.

## Next.js 16 conventions in use

Route component props come from **globally generated types**, not hand-written interfaces — `PageProps<"/interview-session">`, `LayoutProps<"/">`. The route string must match the actual path. `searchParams` is a **Promise** and must be awaited; values are `string | string[] | undefined`, so normalize with a helper (see `firstValue` in `app/interview-session/page.tsx`).

Before writing route/layout/metadata code, check `node_modules/next/dist/docs/` — this version differs from older App Router conventions.

## Style

Tailwind v4 (`@import "tailwindcss"` in `app/globals.css`, no config file). Custom animations and textures are plain CSS classes in `globals.css` (`.voice-bar`, `.speaking-ring`, `.texture-dots`, `.texture-grain`), all with `prefers-reduced-motion` fallbacks. Accent `#5a71f3`. Every screen is dark-mode aware via `dark:` variants.
